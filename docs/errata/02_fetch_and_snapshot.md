# Erratum 02: fetch and snapshot

Where the implementation of spec `02_fetch_and_snapshot` differs from what
the spec says, and why.

1. **Test runtime.** The spec names `@cloudflare/vitest-pool-workers`; the
   project uses its renamed successor `@cloudflare/vitest-plugin` (ADR 01).
2. **Write failures are injected through the env, not test hooks.** The
   spec's check for REQ-2.6 speaks of "the store's test hooks"; the tests
   give the real queue consumer an env whose `SNAPSHOTS` or `DB` fails, so
   production code carries no test seams.
3. **`has_snapshot` is a column** of `links` beside the ones the spec lists,
   so that the link view can say whether Read and Snapshot exist; `notes` is
   a JSON array.
4. **Fixtures are written in code** (`src/worker/fetcher/fixtures/`): the
   PDFs are generated by a small PDF writer rather than committed as binaries.
5. **The website tests run in jsdom**, not happy-dom: DOMPurify does not
   sanitise correctly under happy-dom 21 (ADR 02).
6. **`fetchPage` returns the body it read** (with `truncated` and `tooLarge`)
   rather than a stream, because the 15-second timeout covers the whole body.
7. **The host gate spaces slots 1,050 ms apart**, and a caller waits until
   its slot's time has passed, so that timer jitter never brings two requests
   to one host closer than one second.
8. **The change feed includes the asked time itself** (`updated_at >=
   changed_since`): a change in the very millisecond of a `server_time` comes
   again rather than being missed. A failed refresh also moves `updated_at`,
   so the website's polling of a refreshing card ends.
9. **Failure reasons of a thrown request are read from the error message**
   (DNS → "host not found", TLS/certificate → "TLS error", anything else →
   "could not connect"). The tests fake those messages; the messages the
   Workers runtime really produces were not observed in this run.
